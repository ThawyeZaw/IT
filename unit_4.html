Topic 17: Use of Features of Database Solutions

Understand why databases are used and how they meet user needs

Why Database Software is Used

  • Store large amounts of data while maintaining integrity and security
  • Support multi-user access (unlike spreadsheets)
  • Minimize data duplication through relational structure
  • Provide sophisticated tools for searching, sorting, and filtering

Common Database Applications

Stock Control
Track inventory across retail, distribution, and manufacturing. Automatic reordering when stock falls below threshold.
Ticketing Systems
Central coordination for flights, theatres, hotels. Real-time availability and booking management.
Banking
Store millions of customer accounts. Handle transactions worldwide with data accuracy.
E-commerce
Product catalogs, customer records, sales history, inventory management in real-time.
Key Concept: Database Features
Relational Database
A database made up of multiple related tables with relationships between them to minimize duplication
Transaction
A sale where a customer exchanges money for goods/services, involving multiple database systems

Analyzing User Needs

Information collection methods:

  • Observation: Watch users interact with current system
  • Document Analysis: Review existing forms, spreadsheets, paper systems
  • Interviews: Ask targeted questions to clarify requirements

User Characteristics

Characteristic Impact on Design
IT Literacy Simple interface for low skills; complex for experts
Age Font size, color contrast, navigation style
Language Proficiency Clear terminology, avoid jargon, helpful error messages
Accessibility Needs Keyboard navigation, screen reader compatibility, high contrast

Evaluating Design Appropriateness

Use prototype testing with target users to gather feedback:

  • Create mock-up or prototype of database
  • Demonstrate to representative user group
  • Collect feedback on usability
  • Identify required improvements

Interface Design Factors

Factor Good Practice
Interface Type Graphical (GUI) for most users; text-based for experts
Colours & Fonts Sufficient contrast (dark on light); limit to 2-3 fonts
Complexity Logical menu hierarchy; main functions first
Language User-familiar terminology; clear error messages
Compatibility Test on multiple browsers/devices; responsive design

User Experience (UX) Impact

  • Interface Design: Consistent, user-centred approach with visual hierarchy
  • Ease of Use: Clear labelling, tooltips, predictable behaviour
  • Efficiency: Common tasks easily accessible without multiple menu clicks
  • Help & Support: Tooltips, help buttons, detailed on-screen instructions
  • Stability: No crashes or unexpected errors; thorough testing required
  • Data Accuracy: Reliable calculations; validated data throughout

Topic 18: Relational Database Concepts

Master data structure, relationships, and validation techniques

Database Components

  • Table: Collection of related data (e.g., Customers table)
  • Record: Individual row representing one item (one customer)
  • Field: Column storing one attribute (customer name)
  • Relationship: Link between tables showing data connections

Atomic Data Principle

Fields must be atomic - cannot be split further.

❌ Not Atomic
Name field containing "Ms Amita Patel" mixes title, first name, and family name
✓ Atomic
Separate fields: Title, FirstName, FamilyName

Minimizing Duplication

Critical for database integrity. Example:

  • Create separate Customer table with address once
  • Reference CustomerID in Orders table
  • Prevents inconsistencies if address changes

Data Types

Type Use Example
Short Text Up to 255 characters Names, cities
Long Text/Memo Large text ~1GB Descriptions, comments
Byte 0-255 Small counts
Integer -32,768 to 32,767 Quantities, ages
Long Integer ~±2.1 billion Large numbers
Double Floating-point (15 digits) Scientific data
Decimal Fixed-point, precise Currency, precision calculations
Date/Time Dates and times DD/MM/YYYY format
Currency Money values £, €, $ formatted
Boolean Yes/No, True/False, On/Off Binary choices

⚠️ Common Mistakes

  • Phone Numbers: Use TEXT not NUMBER (includes +, leading 0)
  • Zip Codes: Use TEXT not NUMBER (prevent leading 0 loss)
  • IDs: Use AUTO NUMBER for unique sequential values

Types of Relationships

One-to-Many (Most Common)
One record in Table A relates to many records in Table B.
Example: One customer places many orders.
One-to-One
One record in Table A relates to exactly one record in Table B.
Example: One employee has one company car.
Many-to-Many (Requires Junction Table)
Records in Table A relate to many records in Table B and vice versa.
Example: Students take many subjects; subjects have many students.
Resolution: Create junction/mapping table.

Keys

  • Primary Key (PK): Unique identifier for each record (e.g., CustomerID)
  • Foreign Key (FK): Primary key from another table used to create relationship
  • Composite Key: Primary key made from 2+ fields combined (e.g., OrderNo + ProductCode)

Referential Integrity

Prevents invalid relationships by ensuring:

  • Foreign keys reference valid primary keys
  • Cascade Update: Automatically updates FKs if PK changes
  • Cascade Delete: Deletes related records when main record deleted

Validation Techniques

Technique Purpose Example
Presence Check Field must contain data Is Not Null validation
Range Check Value within acceptable range Age: >=18 AND <=100
Lookup Check Value exists in another table Foreign key must exist
List Check From predefined list Gender: M/F; Status: Active/Inactive
Format/Picture Check Matches pattern Phone: (000) 000-0000
Length Check Exact or maximum length Product code: always 4 characters

Data Entry Quality Improvements

  • Input Masks: Force specific format as user types (e.g., L000 for letter+3 digits)
  • Dropdown/Combo Boxes: Restrict to valid options
  • Radio Buttons: Select one option from limited set
  • Checkboxes: Select multiple options
  • Default Values: Pre-populate common values (e.g., today's date)
  • Help Text & Tooltips: Guide users on expected input

✓ Clear Error Messages

Good: "Price cannot be negative. Please enter a value of 0 or greater."

Poor: "Invalid entry"

Topic 19: Database Solutions

Create databases, forms, queries, reports, and macros

Data Manipulation

  • Insert: Add new records to tables
  • Update/Modify: Change existing record data
  • Delete: Remove records (consider referential integrity)
  • Retrieve: Find and display specific data

Data Retrieval Methods

Filters
Simple: Drop-down arrows on field headers. Quick but not saveable. Use for simple, one-off selections.
Queries
Sophisticated: Saved and reusable. Support complex AND/OR logic, multiple tables, calculated fields.
Reports
Formatted Output: Designed for printing. Group data, include totals, add charts, professional layouts.

Import/Export Formats

  • Import from: Excel (.xls, .xlsx), CSV, TXT
  • Export to: Excel, CSV, TXT, HTML, PDF

Queries

Key Features:

  • Filters records based on criteria
  • Can use wildcards: * (any characters), ? (single character)
  • Supports comparison operators: >, <, >=, <=, Between
  • Can join multiple tables
  • Example: Find all orders over £100 sorted by date

Calculated Fields

Create new information from existing data:

  • In Queries: Total: [Quantity]*[ItemPrice]
  • Aggregations: Sum, Count, Avg, Min, Max
  • Group By: Organize results and calculate summaries

Reports

  • Professional output designed for printing
  • Group data logically (e.g., by department)
  • Include calculations, totals, averages
  • Add charts and visual elements
  • Format for readability with titles and labels

Forms for Data Entry

Key Features:

  • Open ready for new record entry
  • Disable primary key field (use AutoNumber)
  • Combo boxes for lookups from related tables
  • Input validation with clear error messages
  • Save and Cancel buttons with confirmation

Menus & Dashboards

  • Blank form with command buttons
  • Buttons open forms, queries, or reports
  • List boxes for selecting options
  • Logical navigation workflow

Good UI Design Principles

  • Clear, meaningful field labels (expand abbreviations)
  • Mark mandatory fields with asterisks (*)
  • Logical layout following user workflow
  • Visual hierarchy: important items prominent
  • Consistent formatting and colours
  • Back/Cancel buttons to recover from mistakes
  • Help text, tooltips, instructions

Control Features

  • Dropdown lists - restrict to valid options
  • Radio buttons - select one from few options
  • Input masks - force specific format
  • Restrict editing - disable fields user shouldn't change

Macros

Automate repetitive tasks:

  • If/Then/Else: Conditional logic for validation
  • Save Record: Save form data
  • Open Form/Query: Navigate to other objects
  • Close Window: Exit forms
  • Message Box: Display feedback messages
  • Import/Export Spreadsheet: Automate data transfers

Testing

Test Plan Elements:

  • Test Description: What you're testing
  • Expected Result: What should happen
  • Actual Result: What actually happened
  • Pass/Fail: Do results match?

Use Boundary Values: Test just below, at, and above valid limits

  • Validation testing (e.g., age 17, 18, 19 for min age 18)
  • Menu testing (all buttons work correctly)
  • Output testing (calculations accurate, formats correct)

Evaluation & Enhancement

Evaluate Against:

  • Original user requirements - does it meet them all?
  • Ease of use - would non-IT users find it intuitive?
  • Performance - does it work quickly?
  • Stability - no crashes or unexpected errors?
  • Data integrity - calculations accurate?

Suggest Enhancements: Realistic improvements like better UX, additional features, performance optimizations
